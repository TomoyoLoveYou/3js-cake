# 🍰 卡通草莓蛋糕 · Three.js

用 Three.js 做的卡通风格生日蛋糕，单文件 HTML，浏览器打开就能看。

## 预览

直接打开 `cake/index.html`（需联网加载 Three.js CDN）。

## 技术要点

- **旋转曲面建模**：奶油裙、奶油盖、蕾丝盘、草莓全部由一条截面线绕轴旋转生成（`revolveSurface`），不是堆球体。边缘起伏是几何真实的波浪，不是贴图。
- **卡通渲染**：`MeshToonMaterial` + 4 段梯度贴图做硬边明暗分档；每个部件挂一层背面外扩描边。描边几何必须相对自身原点居中，否则缩放会变成位移。
- **程序化贴图**：海绵气孔、草莓籽用 canvas 实时生成（灰度图 × 材质色，换装只改颜色）。
- **手搓控制器**：不依赖 `examples/addons`，拖拽 / 滚轮 / 双指捏合 / 阻尼全部自己实现。
- **光照架构**：暗色背景下环境光补底（0.52）+ 主光（1.55）+ 补光（0.5），梯度贴图最低档抬到 0.71，蛋糕整体提亮且不脏；明暗层次仍靠四档梯度分出来。若换回浅色背景，建议把环境光降回 0.3 以下，否则会洗白。

## 交互

- 拖拽旋转，滚轮 / 双指缩放（竖屏自动拉远相机）
- 自动旋转开关
- 吹灭蜡烛（带烟雾粒子）
- 四套配色热切换：草莓奶油 / 抹茶白巧 / 香芋树莓 / 蓝莓星空
- 复位视角

## 目录

- `index.html` — 当前版本，单文件含全部代码
- `render-clean.html` — 纯净渲染版：隐藏 UI、冻结动画、固定复位视角，用于出视频素材
- `tools/render_to_pixel.py` — 渲染图 → 像素图（轮廓优先，推荐）
- `tools/make_compare.py` — 生成 `video-assets/pixel/compare.png` 对比图
- `tools/make_pixel_assets.py` — 旧流程：48×48 像素图 / 拼豆图纸（众数投票，轮廓会碎）
- `video-assets/` — 生成的视频素材（见下）
- `video-assets/pixel/` — 新流程输出的像素图（多分辨率 + 对比图）

## 视频素材：像素图 & 拼豆图纸

为「3D 渲染 → 像素图 → 拼豆图纸」视频转场准备的静态素材：

| 文件 | 说明 |
| --- | --- |
| `render-reset-view.png` | 复位视角高清渲染（无 UI，已裁掉无头截图白边） |
| `pixel-cake.png` | 48×48 像素图（最近邻放大 16 倍） |
| `pixel-cake@48.png` | 48×48 原始像素图 |
| `perler-cake.png` | 拼豆图纸：豆珠网格 + 坐标 + 色号表（按数量排序） |
| `pattern.json` | 网格数据 + 调色板 + 每色数量，供视频逐格驱动动画 |

色板按渲染图实测颜色校正（Toon 四档梯度 × 材质色），像素图与图纸同源同网格。
换配色主题后，重跑 `render-clean.html` 截图再执行：

```bash
python tools/make_pixel_assets.py   # 依赖 pillow + numpy
```

## 渲染图 → 像素图（轮廓优先）

普通在线工具的做法是「双线性缩小 → 量化调色板」。渲染图里 2~3px 宽的描边缩到 48 格后，
一格里的覆盖率只有 20% 左右，众数/平均都会把它判给邻近的亮色 —— 于是轮廓碎成虚线，
奶油和盘子这种相邻同色材质塌成一块白，颜色信息也跟着丢。48×48 那版（`pixel-cake.png`）
就是这个问题。

`tools/render_to_pixel.py` 换了个思路：**先保住结构，再上颜色**。

1. **色板来自渲染图本身**：对真实出现的颜色做 ΔE 贪心聚类，只留占比够大的簇。
   Toon 渲染的明暗是离散档位，聚出来的就是美术实际用的那二十来种颜色，不做主观调色。
2. **描边单独抽出来**：反向外扩描边在渲染图里本来就是连续的一条线，直接按颜色采样它，
   比事后猜边缘准得多；再用 Zhang-Suen 细化成 1px 中心线，粗描边才不会糊成一坨。
3. **每格按面积占比决定**：中心线穿过这一格 → 描边色；否则取面积最大的材质色。
   比一格还宽的粗描边带，多出来的格子回填最近的主体色，保证轮廓只占 1 格。
4. **收尾只做减法和修补**：删掉不挨线的孤立描边点、吸收抗锯齿抖出来的中性碎点。
   不添加原图没有的东西，也不做抖动（dithering）。

```bash
python tools/render_to_pixel.py --grid 48 64 96      # 输出到 video-assets/pixel/
python tools/render_to_pixel.py --grid 128 --scale 8
python tools/make_compare.py                          # 48/32/24 与常见工具的对比图
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--grid` | 48 | 目标格数，可一次给多个 |
| `--scale` | 16 | 放大倍数（最近邻，保持硬边） |
| `--margin` | 0.05 | 主体四周留白比例 |
| `--min-share` | 0.004 | 色板里颜色的最小占比，调小能留住糖针等细节 |

输出：`cake@{grid}.png`（原始格子）、`cake@{grid}x{scale}.png`（放大图）、
`cake@{grid}.json`（`cells` 网格 + 色板，可直接驱动拼豆图纸或逐格动画）。

**分辨率极限**：这张渲染图的线密度是固定的 —— 描边/暗部带宽 10~18px，48 格时一格 14px，
32 格时一格 21px，24 格时一格 28px。格子一旦比线还宽，采样必然把线摊到相邻格子上。
实测（`video-assets/pixel/compare.png`）：

| 格数 | 结果 |
| --- | --- |
| 48 | 轮廓闭合、盘子还在，能当豆画用；常见工具此时已经丢掉全部描边 |
| 32 | 还能分出两层和盘子，但描边开始占满格子，画面偏重 |
| 24 | 线密度超过格子数，两种做法都不成立 —— 这个尺寸应该照着 32 格重画 |

视频转场建议 128（描边 1 格、盘子花边能分出来），拼豆图纸仍用 48 那套。

## 离线运行

Three.js 走 unpkg → jsDelivr → esm.sh 三个 CDN 依次兜底；三个都失败会显示引导提示。
若需完全离线，下载 `three.module.js` 后把脚本顶部 `CDN_LIST` 换成本地路径即可。
